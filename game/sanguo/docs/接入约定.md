# 三国·谋士 接入网站的约定

这份文档写给负责网站工程的同事，也写给帮她干活的 Codex。说清楚三件事：网站该用游戏的哪些文件，游戏需要网站提供哪些接口，以及上线前还有哪些事要定。游戏这边改接口时，必须同步改这份文档。

## 1. 网站要用的文件

| 文件 | 是什么 | 谁生成 |
|---|---|---|
| `game/sanguo/web/index.html` | 完整的游戏页面，单文件：整本书（目前能玩卷一、卷二）、引擎、配图代码都已内联，只从 Google Fonts 加载字体。目录、存档、章节存档点都在页面里 | 游戏这边运行 `python3 tools/build.py` 生成，生成后提交进仓库 |
| `game/sanguo/content/campaign.json`、`content/v2/campaign_v2.json` | 各卷的内容数据，格式见 `docs/设计说明.md` | 游戏这边运行 `python3 tools/build.py` 生成 |
| `game/sanguo/engine/campaign_core.js` | 规则引擎。纯函数、不碰 DOM，浏览器和 Node 都能用，加载后是全局 `CC`。它是 `game/engine/campaign_core.js` 的副本，两个文件一字不差 | 构建时从 `game/engine/` 复制 |
| `game/engine/campaign_core.js` | 所有书共用的引擎（0.4 起）。网站上别的书（修仙、悬疑等）也应该从这里取，不要各自留冻结副本。0.3 的书可以直接换上它，关系模型的要求只会出提醒 | 手写，见 `game/engine/README.md` |

**推荐的接入方式：先整页挂上去。** 在网站构建时把 `web/index.html` 复制到 `dist/play/sanguo/index.html`，再在小说位里加一个入口链过去。网站构建不需要 Python，因为生成好的文件已经在仓库里。

```js
// scripts/build.mjs 里加一行（由网站这边决定加不加、放在哪个路径）
import { mkdir, copyFile } from "node:fs/promises";
await mkdir(new URL("dist/play/sanguo/", root), { recursive: true });
await copyFile(new URL("game/sanguo/web/index.html", root), new URL("dist/play/sanguo/index.html", root));
```

Netlify 和 Vercel 都会先返回真实存在的静态文件，再走 SPA 的兜底重写。部署后要实际打开 `/play/sanguo/` 确认一下。

暂时不建议把游戏拆进网站自己的 UI 里重写。等玩法稳定了再说，到那时只用 `campaign.json` 和 `campaign_core.js` 两个文件。

## 2. 游戏需要网站提供的接口（可选）

不提供任何接口，页面也能完整玩：玩家打字时用关键词匹配，角色回话用写好的台词。接上下面的接口后，才有 AI 理解玩家的话和 AI 回话。

页面启动时会请求 `api/health`。注意这是**相对路径**：页面放在 `/play/sanguo/` 时，实际请求的是 `/play/sanguo/api/health`。所以要么在这个路径下提供接口，要么加一条重写规则，把它转到网站自己的接口上。现在这个路径会落到网站的 SPA 兜底规则，返回首页的 HTML，页面会认为没有 AI，自动进入离线模式。这是安全的默认状态。

| 接口 | 请求 | 返回 | 说明 |
|---|---|---|---|
| `GET api/health` | — | `{"ai": true/false, "creator": false}` | `ai` 为 true，页面才会调用 `api/sample`。`creator` 为 true 时所有人都能看到创作者视图，公网环境保持 false |
| `POST api/sample` | `{"input": "<一整段提示词>", "tier": "quick"}` | `{"text": "<模型原样输出>", "truncated": false}`；出错返回 `{"code": "rate_limited" \| "upstream_error" \| ...}`，并带非 200 状态码 | 页面自己拼提示词，要求模型只返回 JSON，页面自己解析和校验。单次输出 400 个 token 以内就够 |
| `POST api/events` | 一条试玩事件（字段见下） | 任意 2xx | 可选。不接也不影响游戏 |

**`api/sample` 的风险要先处理好：** 这个接口会把前端传来的任意文字发给模型。直接开放到公网，就等于给所有人一个免费的模型代理。上线前至少要做到：
- 只接受本站来源的请求；
- 限制输入长度，建议 8000 字以内；
- 按 IP 或账户限流；
- 最好要求登录，或者扣积分。

网站现有的 `/api/chat` 已经实现了同源检查、限流和上游错误脱敏，可以复用这部分代码，再把模型换成网站现在用的 DeepSeek 或 OpenRouter。`game/sanguo/server/server.js` 是本地试玩用的零依赖参考实现，不要直接部署到公网。

**试玩事件的字段：** `event`、`ts`、`player`（随机生成的匿名 id）、`build`、`campaign`、`lang`、`ai`、`run`，另外每种事件各有自己的字段。事件类型有 `run_start`、`chapter`、`side_pick`、`choice`、`talk`、`talk_free`、`free_text`、`tab`、`map_view`、`ending`、`survey`。网站已经有自己的 `/api/events` 和数据结构，接入时由网站这边决定：是把这些事件映射进现有结构，还是另开一个集合存放。

## 3. 存档和账户

- 存档只存在玩家自己浏览器的 localStorage 里，键名前缀是 `sd.sg2.`：`runs`（存档列表）、`run.<id>`（每一局）、`ckpt.<id>`（每一局的章节存档点）。不跟账户同步，换设备就没有了。
- 内容更新后，旧存档只要还对得上就能继续，对不上的会标成“来自旧版本”，只能删除。
- 以后要做账户同步，由游戏这边提供存档的导出和导入函数，网站这边负责存储。现在还没做。

## 4. 上线前要一起定的事

- **品牌**：游戏页面目前用的是 StoryDate 的配色和标识，网站是 StoryLove，需要统一。
- **页脚文案**：现在写的是“内部试玩原型，选择会被匿名记录”。公开上线前要按实际的数据收集方式改写。
- **AI 费用**：由谁承担，每局大约调用几次模型，要不要扣积分。一局走完，玩家打字越多调用越多，目前没有真实数据，需要先小范围测一下。
- **年龄与内容**：游戏里只有温芷一个角色可以谈恋爱，而且不写露骨内容。网站其他角色面向成年用户，游戏入口要不要同样设年龄门槛，由网站这边决定。

## 5. 改动边界

| 改什么 | 谁来改 | 方式 |
|---|---|---|
| `game/**`：内容、引擎、游戏页面 | 玩法设计 | 提 PR，CI 自动校验 |
| 网站构建里复制游戏页面的那一步、入口链接、`api/sample`、`api/events` | 网站工程 | 提 PR |
| 本文档里的接口格式 | 双方 | 谁要改，谁先在 PR 里说明，改完同步更新本文档 |
