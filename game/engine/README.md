# StoryDate 互动小说引擎

所有书共用这一套引擎。三国·谋士是第一本，修仙、悬疑等题材的书用同一个引擎、同一套校验。

## 三层

| 层 | 管什么 | 在哪 | 谁改 |
|---|---|---|---|
| 引擎 | 规则怎么运作：选择和条件、账本、回响、叙事债务、关系和五档、说话的后果、开放提问、结局、存档继承、校验、模拟玩家 | `campaign_core.js`、`tiers.json` | 改动要过所有书的校验，升版本号 |
| 题材包 | 一类故事共有的东西：价值观标签、资源的角色、失败的样子、写作清单、额外的校验规则 | `packs/` | 新题材加一个包 |
| 书 | 人物、场景、台词、这本书自己的资源 | 各书目录，例如 `game/sanguo/` | 作者 |

**一本书只选一个题材包。** 题材包不写死变量名，只规定“角色”。比如修仙包要求有“修为”和“资源”两种角色，书里自己决定叫“灵力”“灵石”，再在 `camp.resources` 里对上：

```json
"pack": { ...packs/cultivation.json 的内容... },
"resources": { "power": ["qi"], "currency": ["stones"], "body": ["health"], "risk": ["exposure"] }
```

## 规格版本

| `camp.spec` | 含义 |
|---|---|
| `storydate.campaign/0.3` | 旧书。能照常运行和校验；关系模型的要求只出提醒，不拦。 |
| `storydate.campaign/0.4` | 现行规格。下面这些都会被校验器拦住。 |

0.4 的要求：

1. **关系**：每个人物都有交情（warmth）、信任（trust）、看重（esteem）三根轴，0 到 10。只有产品允许谈恋爱的人物多一根亲近（intimacy）。每个人物要指定剧情看哪根轴（`main`）。
2. **五档**：`camp.tiers` 用 `tiers.json`。剧情里的关系门槛只能落在档位边界上：“≥” 只能写 0、2、4、6、8，“≤” 只能写 1、3、5、7、10。界面和提示用档名，不给玩家看数字门槛。

   | 档 | 数值 | 信任 | 看重 | 交情 | 亲近 |
   |---|---|---|---|---|---|
   | 0 | 0–1 | 戒备 | 轻视 | 冷淡 | 生疏 |
   | 1 | 2–3 | 观望 | 寻常 | 相识 | 在意 |
   | 2 | 4–5 | 可托 | 器重 | 相熟 | 心动 |
   | 3 | 6–7 | 倚重 | 推崇 | 交好 | 两情相悦 |
   | 4 | 8–10 | 心腹 | 折服 | 知己 | 相许 |

   可选的**高档难升**（引擎 0.4.1）：`camp.hard_tiers = {"rel.liubei.trust": 3}` 表示到了第 3 档以后，普通选择的加分不再生效，只有效果上标了 `"key": true` 的关键时刻能再往上推；扣分照常。用于“一路忠心就能轻松到顶”的主轴。

   可选的**说话走向**（引擎 0.4.3）：场景的 `moves`（或全书的 `camp.moves`，用 `nodes` / `except` 限定场景）列出玩家“说出来”就会改变剧情的话，比如威胁、劝说、说漏嘴。每条写清对谁说（`to`）、是什么意思（`means`，给 AI 看）、离线识别用的正则（`match`）或语气标签（`labels`）、旁白（`out`）和效果；`goto` 指向一个当场发作的场景（`kind: "flash"`），`resume` 表示演完回到原场景，否则原场景就此结束。AI 只判断玩家这句话属于哪一条，后果都由规则写死。走向只在主线和支线场景里生效，每条每个场景最多触发一次。

   可选的**处境**（引擎 0.4.6）：`camp.situations` 列出玩家可能落进的处境，每条是 `{id, kind, flag, label, lock?, locks?, lasts?, back?}`，由引擎执行，不用在每个场景里补：
   - `dead`（死了）：选项让这个 flag 变真，这一卷就结束（不写 `ends` 也一样）；网站上不再给“接着玩下一卷”。
   - `absent`（不在场：下狱、被送走）：不再给支线，正文写“这些天，你……，外面的事什么也做不了”。
   - `hurt`（负伤）、`sidelined`（失势）：`locks` 里的选项锁住（`types` 按选项类型、`tags` 按选项标签、`choices` 按 `场景.选项`），锁住的理由用 `lock`；失势时支线少给一个。
   - `lasts`：从出事那一章往后再管几章，到期自动解除，并在新的一章开头讲 `back` 那句话。
   - 突发场景和插入场景不锁（那是正在发生在你身上的事）。校验器会拦住“某个处境让一个场景一个能走的选项都没有”的情况；需要时给这个场景加一个只在该处境下出现的“旁观”选项。
   - 网站的 AI 会拿到 `yourSituation`，台词和旁白不能跟它矛盾。

3. **题材包**：`camp.pack` 是 `packs/` 里的一个包，必需的资源角色都要在 `camp.resources` 里对上变量。选项上的价值观标签只能用包里的。
4. **题材包的规则**（目前三个包都用这三条）：
   - `alt_path`：一个场景里有选项要花资源，就必须有一个不设任何门槛的选项。资源不够，路会变慢、变难，但不会卡死。
   - `earned_victory`：结局只要看了“修为”“证据”这类资源，就必须同时看一个玩家做过的事（剧情标记）。刷数值不能冒充成功。
   - `risk_bites`：每个风险变量至少触发一个场景。到线必须出事，不能只是一个数字。

## 现有题材包

| 包 | 好玩在哪 | 价值观标签 | 资源角色（* 为必需） | 例子 |
|---|---|---|---|---|
| `history-strategy` 历史谋略 | 改得动历史的边，改不动历史的骨 | 义 智 仁 勇 诚 利 | 名声*、风险*、偏离 | 三国·谋士 |
| `cultivation` 修仙成长 | 捷径永远在眼前，每一条都要付代价 | 稳 贪 义 狠 诚 悟 | 修为*、资源*、身体、风险* | 网站上的《谷外微尘》 |
| `mystery-revenge` 悬疑复仇 | 查得清和下不下得了手是两件事 | 真 忍 利 情 义 狠 | 证据*、经费、时间、风险* | 网站上的《余烬与潮汐》 |

包的内容在 `packs/make_packs.py` 里改，改完运行它重新生成 JSON。每个包还带“失败的样子”和“写作清单”，写书前先读。

恋爱题材包还没有写：哪些角色能谈恋爱、谈到什么程度，是产品决定，等定了再加。

## 写一本新书

1. 选题材包。没有合适的，先提出来讨论，不要在书里自造一套规则。
2. 写人物卡：名字、外貌依据、三根轴的初始值（通常在第 1 档，也就是 2 或 3）、剧情看哪根轴、价值观（包里的标签各让哪根轴 ±1）、火气线。
3. 定资源：每个必需的角色对上一个变量，写清楚上下限。
4. 按卷蓝图写：每卷 8 章左右，每章一场主线，0 到 2 个支线（通常先支线后主线；章节写 `"main_first": true` 就先演主线，适合用最抓人的名场面开书）；全卷 2 到 3 个开放提问、2 到 3 场夜谈、1 到 2 笔叙事债务、至少 1 场当场发作；结局碎片不少于 6 组，每片都能追溯到玩家改得动的变量。详见 `game/sanguo/docs/全书规划.md` 的“每一卷的配方”。
5. 关系门槛用档（三国的 Python 写法是 `AT(人, 轴, 档)`、`UPTO(人, 轴, 档)`）。
6. 跑检查，过了才能上线：

   ```
   node game/engine/tools/check.mjs 你的书.json 5000
   node game/engine/tools/check.mjs 卷二.json 5000 --prev 卷一.json   # 后面的卷：连着上一卷模拟
   ```

   上线标准：0 个错误；5000 局随机玩家没有阻塞问题。关系预算表里主轴“饱和”或“几乎不动”的提醒要看一遍，说得出理由才可以留着。

## 旧书升级到 0.4

```
node game/engine/tools/migrate.mjs 旧书.json 新书.json --pack cultivation \
     --res power=qi --res currency=stones --res body=health --res risk=exposure
```

工具会做这些事，并逐条列出来：
- 关系值换到 0–10（初始值按比例换算，+1/−1 的效果不变）；
- 门槛对齐到最近的档；
- 补上缺的轴，从第 1 档起步；
- 写入题材包和五档。

**工具不会替你做的**：给选项标价值观、给人物写价值观。这是写作，不是转换。不写也能跑，只是人物不会对你的选择自动反应。

## 给使用引擎的人

- 网站拿引擎时，只取 `campaign_core.js` 一个文件。它不碰 DOM，浏览器里加载后是全局 `CC`，Node 里用 `require`。
- 公开的函数：`CC.newGame`、`CC.choices`、`CC.choose`、`CC.pickSide`、`CC.endings`、`CC.validate`、`CC.simulate`、`CC.playRandom`、`CC.carryOut`、`CC.compress`、`CC.tierOf`，以及说话相关的 `CC.speak`、`CC.say`、`CC.ask`、`CC.answer`。0.3 时代的调用方式都还能用。
- 每本书目录下的 `engine/campaign_core.js` 是这里的副本，由那本书的构建脚本复制过去。不要在副本上改。CI 会检查副本和这里是否一致。
- 改动记录见 `CHANGELOG.md`。
