# 角色卡规格（草案 0.1，2026-11-11）

> 状态：**讨论稿**，还没有实现。确认后再写代码和迁移。

## 为什么要做

老板 2026-11-11 的意见：角色是素材，故事是用素材做出来的菜。前期由平台用一群好角色、几个好框架做出爆款；后期开放给创作者，让他们决定自己的角色给不给别人用，甚至把不同来源的角色拼在一起写故事（“关公战秦琼”）。前期最重要的是产品，增长不急。

现在的问题：角色写死在每本书的剧本里。同一个角色在不同地方是互不相干的几份数据，比如 Character 页的曹操（`sanguo-characters.js`）和《三国·谋士》里的曹操。灰烬王冠的角色也没法出现在别的故事里。所以要把角色从书里拿出来，单独成卡。

## 三条原则

1. **角色卡只写“这个人是谁”，不写“这个人在某个故事里经历了什么”。** 关系数值、剧情状态、这本书里的身份，都留在故事里。
2. **故事引用角色，不复制角色。** 故事里写 `"cast": ["holmes", "lamp"]`，再按需要补“在这个故事里的身份”。
3. **平台自己先按这套方式做内容。** 我们就是第一批创作者，等开放给外部时，工具已经被我们自己用顺了。

## 一张角色卡

```json
{
  "id": "holmes",
  "name": {"zh": "歇洛克·福尔摩斯", "en": "Sherlock Holmes"},
  "adult": true,
  "source": {"kind": "public_domain", "work": {"zh": "《血字的研究》（1887）", "en": "A Study in Scarlet (1887)"}},
  "owner": "storydate",
  "license": "remix",
  "persona": {"zh": "……（现在 campaign 里的 persona 原样搬过来）", "en": "……"},
  "voice": {"zh": "说话短、准，爱下结论；叫华生“华生”或“医生”。", "en": "……"},
  "canon": [
    {"zh": "世界上唯一的咨询侦探", "en": "The world's only consulting detective"},
    {"zh": "只记对破案有用的知识", "en": "Keeps only knowledge useful to his work"}
  ],
  "look": {"zh": "高瘦，鹰钩鼻，灰色眼睛，深色外套", "en": "……"},
  "art": {"portrait": "game/holmes/art/sprites/holmes/normal.webp", "sprites": "game/holmes/art/sprites/holmes/"},
  "ties": [{"to": "hudson", "zh": "房东", "en": "Landlady"}],
  "romance": false,
  "tags": {"zh": ["推理", "维多利亚"], "en": ["Mystery", "Victorian"]}
}
```

| 字段 | 说明 |
|---|---|
| `adult` | 必须是 `true`。所有角色都是成年人。 |
| `source.kind` | `original`（我们原创）、`public_domain`（公版作品，如福尔摩斯、三国）、`user`（以后的用户原创）。**不收受版权保护的 IP 角色。** |
| `owner` | 谁做的这张卡。平台内容写 `storydate`，以后是创作者的账号 id。 |
| `license` | 别人能怎么用：`private` 只有自己能用；`cast` 别人可以让这个角色出演自己的故事，但不能改人设；`remix` 别人还可以改人设、做变体（变体是一张新卡，记着出处）。 |
| `persona` / `voice` | 给 AI 写台词用：这个人是谁、怎么说话。 |
| `canon` | 不管出演哪个故事都不能违背的事实。拼角色的时候，检查工具用它防止角色走样。 |
| `look` | 给出图用的外貌描述，保证不同故事里画出来是同一个人。 |
| `art` | 已有的立绘和头像，指向现有文件，不复制。 |
| `ties` | 和其他角色卡的固定关系（师徒、搭档、宿敌）。 |
| `romance` | 能不能谈恋爱。**这是产品决定，只能由人来改，AI 不能自行设定。** |

## 故事怎么引用

故事的 `campaign` 里加一个 `cast`，原来的 `chars` 只留下和这本书有关的部分：

```json
"cast": {
  "holmes": {"role": {"zh": "被请来的侦探", "en": "The detective called in"}},
  "lamp":   {"role": {"zh": "案发现场的器灵", "en": "The relic spirit at the scene"}}
},
"chars": {
  "holmes": {"dims": {"warmth": [2, 0, 10], "trust": [2, 0, 10], "esteem": [2, 0, 10]}, "main": "esteem"}
}
```

人设、外貌、立绘从卡里来；数值、在这本书里的身份留在书里。旧书不用一次改完：`chars` 里还写着 `persona` 的，引擎照旧读，不受影响。

## 拼角色（“关公战秦琼”）的规矩

- **故事世界的规矩归故事所有者定。** 福尔摩斯走进灰烬王冠的维斯特林，就照维斯特林的魔术规矩来。
- **角色的人设归角色卡定。** 福尔摩斯到了哪里都还是福尔摩斯，`canon` 不能被故事改掉。
- **授权检查**：故事用到的每张卡，`license` 必须允许（`cast` 或 `remix`），或者卡是作者自己的。
- 检查工具（`check.mjs` 加一项）：`cast` 里的卡都存在、都是成年人、授权允许；台词不违背 `canon`（先人工审，以后再自动）。

## Character 页怎么接

Character 页的每个角色改成“一张角色卡 + 若干个相遇场景”。场景（开场白、地点、起手选项）留在网站的数据里，人设和立绘从卡里来。这样同一个曹操，在 Character 页聊天和在《三国·谋士》里出场，是同一个人。

## 卡放在哪

- 平台的卡放在仓库根目录的 `characters/<id>.json`。每张卡一个文件，方便 review 和以后按卡授权。
- 内容归兰馨 review（角色属于“故事和角色内容”），格式和检查工具归引擎。

## 要你拍板的

1. 授权分三档（`private` / `cast` / `remix`）够不够，还是先只做“给 / 不给”两档。
2. 演示短篇选福尔摩斯 × 灰烬王冠，还是别的组合（比如三国谋士 × 汐川）。
3. 旗舰作品选哪一部来打磨到“爆”的水准。我的建议是灰烬王冠：美术、配乐、机制都最完整。
