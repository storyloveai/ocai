Live payment verification must distinguish successful session/Elements loading from a completed charge and webhook credit fulfillment. No live charge is performed by the agent.

Verification results: all 48 regression checks pass. The published quick view was checked at the measured desktop size. The live public config reports payments, embeddedPayments and walletConfigured enabled. A real Google account sign-in succeeds, but the authenticated wallet fails before reaching Stripe. Safe server diagnostics show auth/internal-error, upstream PERMISSION_DENIED (403), reason SERVICE_DISABLED while checking revocation through Firebase Authentication. This is a disabled Google API dependency, not an expired client session. The browser cannot access the Google Cloud Console (Site Unavailable), so the project owner must check/enable the Identity Toolkit API in the Firebase project and any credential consumer project reported by Google. Do not remove revocation verification to work around this failure. No live Checkout/Elements success or paid fulfillment is claimed until the dependency is fixed and reverified.

Credential handling accepts actual/escaped newlines, CRLF and JSON-quoted PEM environment values. Errors distinguish server credential failures (503) from expired/revoked tokens (401); diagnostics log only safe error codes/status/reason enums, never provider bodies, credentials or account details. Quick-view cleanup now handles native asynchronous close events without restoring stale scroll/focus after navigation or replacement.
