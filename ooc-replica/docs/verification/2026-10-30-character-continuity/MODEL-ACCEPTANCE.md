# Preview 上的角色连续性验收

使用已配置真实模型的 Preview 手动试玩；本轮未调用付费模型。以下是验收场景，不是预先写入聊天的事件。人物实际说过什么，应以该局为准。

| 场景 | 操作 | 应观察到的行为 |
|---|---|---|
| 沈砚舟 · 末班车之前 | 让他解释离开的原因，听完后明确说「这件事已经讲过了，我们说下一件」 | 回应下一件事，不反复退回「你想听解释吗」 |
| 沈砚舟 · 一通未接来电 | 拒绝进门，提出在门外谈；他同意并走出来后继续聊 | 后续动作沿用门外的位置，拒绝不会反复被同一邀请打断 |
| 任一人物 | 提出明天再见，但明确说尚未决定；之后问对方怎么看 | 不将提议写成双方已经答应的约定，更不能写成已经见过面 |
| 陆闻笙 · 最后一个音 | 给出具体音乐意见，再表达相反意见 | 结合人物自己的工作目标解释、尝试或反对，保持与玩家交流的余地 |
| 林照晚 · 照片背面的空白 | 提出保留裂痕，之后再改变决定 | 行动回应最新决定；不替玩家编造照片里的人或家庭创伤 |
| 温芷 | 在独立网站对话中说明身份，逐步建立信任 | 不认定玩家就是书里的子衡，不声称读取剧情存档，不开场默认恋人关系 |
| 长聊和记事 | 记住早期约定，聊到早期消息离开近期窗口，再询问；之后在新消息中明确纠正约定 | 能在有来源的记事覆盖范围内继续，优先尊重近期纠正；不会宣称记得所有未提供的细节 |
| 分支和相遇 | 在约定前另开走向，或开始另一场相遇 | 之后才发生的事不进入此前走向；不同相遇不共享初始关系和记事 |
| 中英文 | 上述场景分别使用自然中文和英文输入 | 回复及建议使用用户实际语言，动作与对白分层；不强制每次提问或制造危机 |

记录具体失败原句、角色、相遇、走向和模型版本，再决定调整提示词还是应用逻辑。模型偶尔漏掉事实不能通过浏览器模拟测试判为已解决。
