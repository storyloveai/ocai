# 批量内容与 API 对接

不需要新建网站。沿用当前前端、服务端 API、Firebase 登录和存档。现有 `/api/chat` 已支持创作字段扩写和流式对话；图像适配器待确定供应商后接入，当前不请求图像、不自动发布目录。

## 提供哪些信息

把以下**非密钥信息**发在对话里即可：

1. 文本和图片供应商名称、官方 API 文档链接、模型名称。
2. 图片接口是立即返回，还是返回 task ID 后轮询；是否支持参考图、角色一致性、比例/尺寸、负面提示词。
3. 首批数量、语言、画风和单批预算。例如“先做 5 本中文都市悬疑，每本封面 1 张、详情场景图 3 张”。

密钥由账号持有人直接填入 Vercel 项目的服务端环境变量；不要发聊天、提交 Git 或使用前端公开变量。确定供应商后再给出准确变量名和所需权限，保留现有文本模型与回退配置。不必为接入 API 另买域名或搭一个站。

## 每本小说的内容包

| 字段 | 用途 |
| --- | --- |
| id、版本、语言、分类、标签 | 批处理关联、重试与目录排序 |
| title、shortDescription | 列表标题与一句话简介 |
| description、prologue、playGuide | 展开详情、序章与玩法介绍 |
| storyBible | 世界观、人物目标、口吻、边界和不能变动的事实 |
| cast 与视觉设定 | 稳定人物外貌、服装、配色和参考图 |
| coverJob | 竖版封面提示词、比例、生成状态与最终资源地址 |
| galleryJobs | 多张详情图，各自的场景、出场人物、比例与资源地址 |
| opening、openingSuggestions | 首次进入时的场景和三个不同的初始行动 |
| reviewStatus、assetStatus | 草稿审核和图片完成状态；两者通过后才可发布 |

现有 80 条草稿已覆盖标题、题材、简介、开场和封面任务；完整人物设定、长篇详情、多张场景图任务仍需扩展。`catalog-drafts.json` 与 `cover-jobs.jsonl` 是当前可用文件，并非全部字段都已生成。普通互动故事也不等于三国那样的规则战役，拆书需另设章节、变量、分支和结局。

## 批量生产流程（待图像 API 接入后实施）

一句话创意 → 结构化故事草稿 → 固定人物/画风 → 封面与详情图任务 → 逐项校验和人工预览 → 发布。

任务按 storyId + 内容版本 + 图片槽位记录状态，限制并发、失败单项重试，已有成功图片复用。先验收少量样本，再执行整批。不同供应商的异步任务和图片下载有效期需依据其文档适配；生成结果应转存为稳定资源后再发布。不会把一整批图像请求塞进一次浏览器等待。

## 对话和三个提示

开场与人物设定可以提前批量生成；后续对话必须实时结合玩家输入、最近剧情和存档。无需为每次聊天重新生成封面。

当前普通故事/角色会在一轮 AI 正文完成后，通过独立的 `task: suggestions` 短请求，基于服务端世界观和最近八条以内消息生成三个不同方向的可选行动。复用当前模型和失败回退，正文打字机输出不等待提示请求。新一轮会取消旧请求；成功结果跟随该条回复存档，刷新无需重新生成。失败、取消、模拟模式不冒充生成成功，也不退回一遍遍重复的开场选项。三国的规则选项继续由既有战役引擎负责。

此处的三个建议不是固定剧情分支或保证成功的结果，玩家仍可编辑或自行输入。此短请求会增加少量模型用量；大规模使用时可进一步并入服务端结构化输出或缓存策略。
