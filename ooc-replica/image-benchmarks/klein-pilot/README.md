## 为什么不能只凭模型名字下结论

- `flux-3-image-klein` 是文档中的服务模型别名；没有检验其实际底层权重或版本。
- 文档说明服务会自动扩写提示词。发送的原文可保持一致，但实际进模型的文字可能不同；仅记录服务返回的 `revised_prompt`，缺失就标记未知，不编造。
- 服务忽略 `size`、`n`、`response_format`；每次一张，实际尺寸从 PNG 读取。原图不裁，HTML 只等比显示。
- 历史内置工具没有暴露模型版本、seed、生成延迟，不能比较速度或跨模型复现性。seed=103 仅用于团队服务内部追踪。
- 两张生成和一次编辑只能用于小样筛选，不能证明全量一致性、稳定性或性能。

## 在能连通网关的电脑运行

仅需 Python 3 标准库，不需要安装 OpenAI SDK。先把本目录完整取到一个独立目录，避免影响正在开发的工作区。

先只检查材料、生成静态报告（**零网络请求**）：

```bash
python3 run.py --out ../klein-results
```

从用户给的 API 文档复制 Base URL。以下命令将隐藏输入测试 Key；不要把 Key 写进命令、脚本、截图或 Git：

```bash
python3 run.py --out ../klein-results --run --only gu-chengye \
  --base-url '这里填文档的 HTTPS Base URL' --key-stdin --archive
```

第一张成功后打开 `../klein-results/index.html`，再继续三项小样：

```bash
python3 run.py --out ../klein-results --run \
  --base-url '这里填文档的 HTTPS Base URL' --key-stdin --archive
```

已有成功结果会校验输入和文件 SHA-256 后跳过，不重复发请求。所有请求串行；任何一项失败就停止，**不自动重试可能已经计费的调用**。单次最长等待 600 秒，与文档排队行为一致。仅请求用户指定网关，不切换到其他厂商或内网固定密钥。

也可以通过专用环境变量 `ZEN5_API_KEY` / `ZEN5_IMAGE_BASE_URL` 提供配置。网关 Key 与内网服务固定 Key 是不同凭据，不可混用。

## 交付与审图

加 `--archive` 会把结果打成同名 ZIP，方便发回评审；ZIP 不包含密钥。

输出包含原始 PNG、实际分辨率、字节数、SHA-256、请求与返回 seed、客户端耗时，以及左右对比 HTML。没有图的项目保留为空，不显示虚构评分。请求错误不记录密钥或完整上游响应。

返回 `klein-results` 后，重点按以下顺序审：

1. 硬约束：成年人、人数、无露骨内容、无字/水印、手和肢体、人物是否完整入镜。
2. 产品适配：半写实角色画风、脸与眼神吸引力、暗金页面里的清晰度、原构图与实际尺寸是否适合人物卡。
3. 编辑保真：是否只改背景和光照，脸型/五官/发型/服饰是否漂移。
4. 服务表现：成功率、扩写是否跑偏、原尺寸、耗时。成本只按你们实际计费或资源数据记录，不从延迟猜成本。

最后形成“哪些用途可以用团队服务、哪些保留内置工具”的样图结论，再决定是否接入批量流程。PR 保持草稿，不合并。
