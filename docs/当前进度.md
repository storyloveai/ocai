### 怎么不撞车

1. **任务只走 GitHub issue。** 标签 `codex` / `claude` / `需要人`。开工前在 issue 里留言“Codex 认领”或“Claude 认领”。没有 issue 的活，先开一个再做。
2. **分支前缀**：Codex 用 `codex/…`，Claude 用 `claude/…`（旧分支名不改）。
3. **开工前**：拉最新 `main`，看一眼还开着的 PR（`gh pr list`）。别人的 PR 正在改的文件，你不要动；需要就在那个 PR 或 issue 里留言。
4. **需要对方区域的改动**：不自己改，开 issue 打上对方的标签，写清楚要什么（比如“三国首页 banner 跳转要带上 `?choice=`”）。
5. **PR 说明写三件事**：改了什么、怎么验证（含 Vercel preview 链接）、对方要不要跟着动。PR 写 `Closes #编号`。

### 上线规则

- **两边都只开 PR，停在 Vercel preview。** 用户看过 preview 说“合并”，才由开这个 PR 的助手合并到 `main`（`main` 会自动部署到线上）。
- 合并前先把 `main` 合进自己的分支，重跑检查。
- 合并后在本文件“最近完成”里加一行。

### 怎么知道对方在做什么

看 GitHub：开着的 PR、带“认领”留言的 issue、本文件的“进行中”。不靠聊天转述。
