## 上线前还差的外部条件

当前 billing 默认 off。Preview 配置最后检查记录见 [暂停时证据](../verification/assets/credits-v1/preview-config-scopes.png)，本轮未得到用户“配置好了”的答复。不要再索要或搬运生产密钥；在托管平台直接设置独立测试环境。

测试环境需要：

- Firebase 测试项目的客户端四项（API_KEY、AUTH_DOMAIN、PROJECT_ID、APP_ID，均以 FIREBASE_ 为前缀），以及同项目服务端 CLIENT_EMAIL、PRIVATE_KEY；配置留在平台。
- Firebase 控制台启用 Google 登录，Authorized domains 允许实际 Preview 域名。测试身份与 Production 隔离。
- 测试 Stripe key/webhook secret、三个测试 price、APP_URL 指向实际 Preview，`CREDIT_BILLING_MODE=test`；Stripe 模式也必须为 test。不得把 live key 或 live 钱包用于 Preview。
- 名称/范围只读检查支持 `node scripts/audit-payment-env.mjs --target=preview --branch=codex/credits-v1-20261112`；只在已有托管身份环境运行，不把 token 传入命令行或聊天。名称存在不证明值有效或登录成功。

TTL 具体目标（不是金融账本）：

| collection group | field | 范围 |
| --- | --- | --- |
| replica-credit-responses-test | expiresAt / Timestamp | 测试临时结果 |
| replica-credit-response-parts-test | expiresAt / Timestamp | 测试临时分块 |
| replica-credit-responses-live | expiresAt / Timestamp | 正式启用前配置 |
| replica-credit-response-parts-live | expiresAt / Timestamp | 正式启用前配置 |

不能对钱包、消费凭证、流水、订单回执设置这个清理策略。TTL 和远端运维可能产生云端费用，本轮只准备计划；获准后在控制台启用 test 两组，创建到期测试结果，核对读取立即拒绝、后续物理删除。live 两组在正式上线批准时另验。维护工具的 `--scan` 只读，`--apply` 才删除临时结果，本轮均未执行远端操作。

## 测试环境就绪后的固定验收顺序

1. 两个真实测试账号：登录、余额、私有作品/历史隔离；两台设备保存/恢复，云端故障不覆盖。
2. 用户批准少量测试点数后，由受控活动发放，核对名单外拒绝、重复领取不增加；同价消费且赠送/购买分账。
3. 经批准的模型预算内验证聊天、作者、图片和游戏各一次成功/失败；重复恢复不再扣，取消/断线按最终服务端状态核对。不能用模拟图推断真实画质。
4. 用户在 Stripe 测试结账执行购买；核对签名 webhook 一次到账、重发不重复、取消/失败不到账；退款/拒付暂停及恢复正确。
5. 核对 TTL、PostHog 漏斗、用量日志和真实成本。确认价格、条款、补贴总预算和 live 开关；再请求用户批准上线/合并。
