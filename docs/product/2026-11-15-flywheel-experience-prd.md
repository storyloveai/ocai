# PRD：StoryDate 飞轮体验版（老板理想版交互原型）

任务 [#154](https://github.com/storyloveai/ocai/issues/154)。2026-11-15 夜间构建，分支 `codex/flywheel-experience-20261115`（基于 main `c688a97`）。

**本文的分工**：第 2 节是老板明确说过的方向（用户转述 + 附件《Storydate怎么打 - Claude.pdf》第 1–3 页的飞轮图与比方）；第 3 节是 PDF 第 4–5 页的盘点与 Claude 建议（**不是老板原话**，只作输入）；第 4 节起是我的实现决定，可被推翻重做。这是一个**交互原型**：验证"老板的理想长成网站是什么样"，不是上线承诺，不改现有内容与玩法。

---

## 1. 一句话目标

把老板的内容飞轮做成**可点、可玩、可看懂**的网站体验：用户从故事进来 → 在故事里认识角色 → 角色沉淀为独立资产 → 角色能回到聊天、走进别的框架的故事 → 创作者（第一阶段是我们自己）用同一套锅和规矩做新菜。

## 2. 老板的方向（实现必须服从）

1. **角色是食材，故事是菜。** 用户真正消费的是故事；玩完一道菜，记住的是里面的人。
2. **一道菜 = 好食材（角色）+ 厨房的规矩（宇宙）+ 一口好锅（框架）。** 同样的锅和规矩，换一批食材就是一道新菜。
3. **入口是故事**：用户不会为陌生角色而来，先被故事打动，在故事里认识角色。
4. **沉淀的是角色**：故事玩完会结束，角色反复出场——在别的故事里、在聊天里、和别人的角色同台。
5. **宇宙是容器**：角色要能混在一起，必须有共同的世界规则；规则清楚，角色再多也不乱。
6. **前期做好一群角色、一个故事、几个框架**，把单点做到极致，前期不追增长追产品。
7. **阶段二才有 UGC**：创作者做自己的角色、自己决定给不给别人用、不同创作者的角色组合写故事。**前期由平台自己做内容。**

## 3. 输入（非老板原话，仅参考）

PDF 第 4 页盘点：五部能玩（三国八卷、灰烬王冠卷一、汐川、贝克街、Character 聊天）；缺"角色锁在各本书里（同一个曹操两份数据）""框架只有我们自己会用""没有可信的看用户能力"。第 5 页 Claude 建议：先记录关键行为、两个候选让用户投票、先打角色卡与宇宙设定的地基。本原型吸收其中"角色卡地基"一条；"看用户"已由 #149/#151 在主线推进，本原型不重复建设。

## 4. 范围与模块设计

### 4.0 数据层：统一角色卡索引（一切模块的地基）

新建**只读**的角色卡数据文件（站点侧），把散在各书/Character 页的角色聚成**一处数据、多处引用**：

```
card = {
  id, name: {zh, en},
  source: { work, framework, universe },     // 出处：哪道菜、哪口锅、哪个宇宙
  portrait,                                   // 复用仓库现有立绘路径
  persona: {zh, en},                          // 人设
  voice: {zh, en, samples: []},               // 说话方式 + 原作例句（引用现有剧本台词，标注出处）
  appearance: {zh, en},
  locked: {zh, en},                           // 不能违背的设定
  appearances: [{ work, role, url }],         // TA 出场/可出场的故事（含聊天）
  chat?: url, story?: url                     // 现有入口直连
}
```

- 数据**全部摘自仓库现有内容**（game/*/content、Character 页数据、设定集文档），不新写设定；例句引用原剧本并标注出处。
- 收录范围：有定稿立绘 + 有明确人设的角色（汐川 5、三国主要角色、灰烬王冠、贝克街、Character 页原创），目标 25–35 张。
- 不迁移、不替换现有数据文件——只是索引层，原书原页照常工作（回应"两份数据"问题：从今往后新体验只认这一份索引）。

### 4.1 角色库 `/characters`（核心模块）

**目录页**：筛选条（全部 / 按宇宙 / 按框架 / 可聊天）+ 响应式卡片网格。卡片=立绘 + 名字 + 一句话人设 + 出处徽章。手机单列沉浸、桌面多列。

**档案页 `/characters/<id>`**（交互重点，"食材档案"）：
- 首屏：大幅立绘 + 名字 + 一句话定位 + 双 CTA（去聊天 / 去 TA 的故事）
- 档案区块：人设 / **说话方式（含原作例句，引用式排版）** / 外貌 / 不可违背的设定
- "TA 的出场"：横滑时间线列出角色在各故事中的身份，点击直达
- "同一宇宙的其他食材"：同宇宙角色横滑，互相跳转——体现"角色能相遇"
- 空态/缺失立绘有占位与说明，不冒充定稿

### 4.2 宇宙页 `/universe`（厨房的规矩）

- 宇宙卡片入口（维斯特林为主，三国/汐川并列为各自容器）
- 维斯特林详情：**规则 / 地点 / 势力 / 时间线** 四页签；时间线横向可拖拽；每条目可跳相关角色卡与故事；数据摘自 `game/ashen` 现有设定文档（只读）
- 明确表达"规则清楚，角色再多也不乱"：每个宇宙页头显示"本宇宙的角色 n 个 · 故事 m 部"

### 4.3 框架页 `/frameworks`（两口锅）

- 双栏对照：**谋士模式**（关系三轴/五档/说话推剧情/处境）vs **galgame 模式**（好感隐藏/共通线→个人线/双结局），各附"用这口锅做出的菜"（书目直连）
- 强调引擎保证：数值与结局由规则决定、AI 只演（这是现有引擎事实，原样表述）
- **互动演示「同一句话，锅怎么接」**：选一句玩家台词，并排展示两个框架各自的接法（打标/关系变化/走向）——用现有引擎文档中的映射做静态示例，标注"演示数据，非实时 AI"

### 4.4 创作者工作台 `/studio`（阶段二的地基，明确标注原型）

- 三步建卡：① 基础（名字/头像选现有立绘或占位）② 人设（人设/说话方式/不可违背）③ **授权（给不给别人用 + 范围开关）**——老板原话里"自己定"做成真实交互
- 实时卡片预览（与角色库同款卡面，所见即所得）
- **拼角色**：勾选 2+ 张卡 → 按模板生成"关公战秦琼"式故事前提（纯模板拼装、无 AI、明确标注演示）
- 草稿存 localStorage + 导出 JSON；页头常驻"原型演示 · 数据只在本机 · 创作者平台尚未开放"

### 4.5 首页故事入口动线（最小侵入）

- 新增"从故事认识角色"区块：任选一部作品 → 展开其角色条 → 直达角色档案（把"入口是故事"做实）
- 导航加入 角色库 / 宇宙 / 框架 / 工作台；现有首屏、书库、分类全部保留

## 5. 通用交互标准

- 中英双语全量（沿用站点 i18n 机制）；手机 390×844 与桌面 1366 双档验收
- 沿用金白品牌与现有字号/间距尺度；新页面不得引入新字体或破坏现有 CSS 变量
- 每个列表有空态；每个外跳有明确去处；不伪造任何"已上线"能力（聊天/游戏跳转都去现有真实页面）
- 不发新的统计事件类型，不接 PostHog 新口径（避免与主线统计冲突）

## 6. 明确不做

- 不改 `game/**` 剧本、引擎、生成文件；不写新故事/新角色设定；不动 #149/#151
- 不做后端/账号/计费/UGC 存储（工作台仅本地原型）
- 不合并、不碰 main、不碰密钥、不花钱、不发点

## 7. 自验收标准

1. `npm run build` + `npm run check` 全绿（含新增测试）
2. 真浏览器桌面 + 手机视口全流程走查：五个模块逐页截图，存 `docs/verification/`
3. 角色卡数据抽查：至少 10 张卡的例句/设定能在原文件中找到出处
4. PR 正文含：改了什么、怎么验证、谁不用跟着动

## 8. 交付节奏

夜间随时推分支保存进度；完成后开 PR 停 preview；用户醒来验收，"合并 #N"才合并。
