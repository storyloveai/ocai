# StoryDate 角色发现体验（#154 / PR #155）

2026-11-16 用户授权收敛重做。本文描述当前实现，取代初版的四栏目、三步建卡和拼角色演示方案。

## 方向与实现的区别

老板的方向以用户转述为依据：角色是食材、故事是菜；前期做好一群角色、一个好故事和几个好框架，以平台内容吸引用户，再带动创作者。创作者日后可决定是否允许别人使用角色，并合作创作。

“宇宙是厨房规矩”“入口必须是故事”“一道菜的三要素”属于此前的产品推演，不应写成老板原话。角色库、世界目录、框架介绍也不等于已经实现了跨故事记忆、角色资产、授权或 UGC 平台。

本轮决定：先让用户找到有兴趣的角色、了解人物、进入已有故事或聊天。减少功能数量和内部术语，创作复用已有工坊。

## 当前范围

| 入口 | 当前行为 |
| --- | --- |
| 首页底部 | 四部作品的角色预览；点击直达对应角色筛选；只有一个“认识更多角色”主按钮 |
| `/characters` | 33 位现有角色，按故事世界/可聊天筛选，中英文名字和关键词搜索；无结果有空态 |
| `/characters/<id>` | 立绘、简短介绍、已有故事/聊天；支持本地化表情切换；详细人设默认折叠并提示剧透；原作节选明确出处 |
| `/universe`、`/universe/<id>` | 可选的五个故事世界介绍，背景/地点/人物与势力/时间线页签，链接相关角色与故事 |
| `/frameworks` | 可选的四种玩法介绍，直接链接已有作品；没有静态数值或伪装成引擎结果的演示 |
| `/studio` | 旧地址保留，导向既有 `/builder`；原型旧草稿只读、可导出，不再写入或删除 |

局部导航只保留“角色 / 故事世界 / 创作”，不再给全站侧栏加四个入口。原站 `/character`、`/builder`、账户和计费流程继续使用现有实现。

## 删除的交互

- 不生效的授权开关、借用角色立绘的建卡向导、模板拼角色和重复的草稿编辑器。
- “同一句话三锅对比”及未经引擎验证的数值、结局暗示。
- 面向用户的“老板说”“食材/锅”“飞轮/阶段二”等内部表达。
- 大面积金色按钮、金框与渐变、卡片抬升、缩放和错峰入场动画。

旧 `sd-flywheel-drafts` 数据不改动，语言切换和页面浏览均不会重写。损坏 JSON 可导出原始备份；浏览器拒绝读取时显示提示，不伪装成“没有草稿”。

## 视觉与交互标准

- 白色主按钮：`#fafafa / #171717 / 8px / 500`；次按钮为深色描边，触区至少 44px。
- 保留品牌标志和故事原图的颜色；界面以中性灰、白为主，不另造一套金色按钮系统。
- 桌面标题区收紧；390px 手机档案单列，表情按钮不压缩、可横滑。
- 世界页签具备关联的 tab/tabpanel，支持左右方向键、Home、End；隐藏区明确不占位；保留 reduced-motion。
- 语言切换保留搜索词、表情和当前世界页签；重绘后刷新原站账户侧栏，避免残留首页选中状态。

## 数据与边界

角色数据来自现有剧本及站点角色模块，不改 `game/`。32 条原作节选出处均提供中英版本；修正沈澄出处、提灯/福尔摩斯/卡罗引文偏差及三国范围描述。周瑜、吕布、貂蝉复用的图片明确标注为现有故事封面，不能冒充定稿立绘。

独立游戏链接保持 `target="_top"`，页面提示其进度尚未与角色聊天同步。夏知遥账号闭环及积分仍分别属于 #149 / #151；本 PR 不接尚未合并的路由，也不宣称已经连通。将来合并前需再做两条主线的集成验证。

不接后端、不增加计费或埋点、不读密钥、不调用付费 API。只更新当前 PR，用户明确说“合并 #155”前不合并。
