# 夏知遥：聊天与汐川剧情进度互通

日期：2026-11-12。任务：[#148](https://github.com/storyloveai/ocai/issues/148)，PR：[#149](https://github.com/storyloveai/ocai/pull/149)。从 GitHub main `c688a97e905ca6ee2dedd68d718411593e7eee82` 开始，分支 `codex/zhiyao-story-loop-20261112`。接续 #146 / #147 的网站体检。本轮由 Codex 接手播放页工程，未修改剧本、机制或决策记录。

## 用户可体验的变化

- 角色目录增加夏知遥，采用已定稿立绘。入口 `/play/xc-zhiyao`。服务端直接复用同步的 `xichuan-campaign.json` 中 zhiyao 的人设，不复制另一套隐含设定。
- 聊天上方始终显示当前汐川进度和故事入口。首页汐川卡片改到 `/play/xichuan`，包裹现有完整游戏；页面有回聊天入口。
- 游戏自动存档、9 个手动档、已读、回想和设置使用现有账号存储接口。等待账号恢复后才加载游戏；账号切换立即卸载旧界面，旧 scope 的迟到写入被丢弃。存档 key 已在现有 Firestore 同步允许列表内。
- 独立页面 `/assets/xichuan/index.html` 保留，继续使用原来的 `xc.*` 本机存档。未登录的新入口可复制旧进度，不删除原存档。已登录且无存档时，只显示主动导入按钮，不自动认领设备上的游客或旧版数据；有账号存档时不覆盖。
- 每句台词和选项停顿处保存当前状态。聊天和推荐回复拿到同一份、经过类型和白名单限制的当前剧情事实，涵盖入社、约定、失约、决裂、已知秘密及关系状态。读旧档/重开会替换当前事实；旧对话记录仍保留，并在模型指令里明确不能把其他存档分支当作当前已发生剧情。剧情推进、修复决裂仍由游戏规则执行，聊天不直接改游戏状态。
- 历史列表分别列出汐川故事与夏知遥聊天。修复游戏选项层挡住存读档按钮、标题层挡住回想面板的问题。
- 新增 `xichuan_chat_returned`、`xichuan_progress_imported`；复用 game_opened / game_scene / game_chapter_reached / game_volume_ended。只传固定游戏、人物、章节和节点 ID，不传对话、选项文本、存档或私人资料。本地与自动化浏览器不开统计。

## 本轮边界与后续验收

- 不新增收费点，不扣积分，不做真实支付；收费边界仍需产品决定。
- 模型侧使用的是客户端上报的当前存档投影，不能充当服务端认证的成就或计费凭证。
- 云存档复用了现有账户服务，自动化用模拟账户/云接口验证；真实 Firebase 双账号、跨设备同步、真机手机与真实模型的长期记忆/拒绝/不剧透效果仍需验收。
- 对话的走向分支与游戏存档分开管理；本轮所有聊天走向引用当前正在玩的那一份游戏进度，没有建立多世界/多角色迁移系统。
- PR #140 的两个目录数量测试与本轮小幅重叠，已在该 PR 留言说明；未改其生成角色目录和 reference.js。PR #144 角色卡讨论稿已知会本轮采用现有 persona 的接入方式。
- 停在 PR Preview，未合并 main。
