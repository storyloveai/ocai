# 完整动线实玩后的第三轮减法

任务 #156 / PR #157，2026-11-17。用户要求自己从头体验“角色 → 聊天 → 故事 → 回到聊天”，不顺直接改，继续不合并。

## 发现与修改

1. **人物与聊天之间绕圈。** 目录筛选来源仍保存在 history 中，但返回人物时聊天来源抢了优先级，唯一返回入口又指向聊天。现在真实 Story 来源优先，其次是经过白名单校验的原目录，再其次才是直接聊天；从目录开始的用户可以带着原筛选退出这条路。没有目录来源的直接聊天仍能返回聊天，不接受外站或人物子页冒充目录。
2. **同一个编辑弹窗放了两个按钮。** 回复上的“编辑回复”和“消息选项”都是相同 handler；删后者，复制、重试、明确编辑、原话记事和另开走向保留。
3. **已有聊天仍重画开场。** 夏知遥已有消息后，不再反复显示最初相遇或固定的“她放下手里的东西，等你开口”；保留人物与场景标题、原消息。空聊天仍有原作开场，其他角色不变。
4. **手机游戏重复网站导航。** 游戏已有顶部来源返回和原生控制条，撤下此页的网站底部导航并释放原占位；返回聊天或人物后网站导航恢复。电脑侧栏保留，iframe 继续按实际可用高度测量，未改原生游戏控制或存档。
5. **“继续故事”承诺与游戏不符。** 当前公开接口启动后固定进入游戏标题页；网页上的入口改为“回到故事 / Return to story”，新玩家仍是“进入故事”。继续和读档沿用游戏原生入口，不伪造自动续玩。

## 本机完整实玩记录

Chrome，隔离本机站 `127.0.0.1:3032`，390×844 开始，后切到 1366×900 / 英文。站点明确关闭模型与计费，生成 POST 全部拒绝。没有向浏览器注入消息、进度、账号或存档。

1. 目录选汐川，搜索“夏”，打开唯一结果夏知遥；开始聊天。
2. 实际发送“我愿意加入电影社，一起把潮声影院留下来。”，收到明确标注的 Demo 回复；把用户原话记住，再留下未发送草稿“等我看完放映会，再来和你聊。”。
3. 从聊天进入故事，点击开始游戏，沿原生对白推进；先选“……来看它最后一个春天。”，再在入社选项选“当场填表。”。宿主进度实际更新为“第 1 章进行中 · 你已加入电影社。”。
4. 返回聊天，原两条消息、一条记事及未发送草稿都在。发送原草稿，新的 Demo 回复同时带出已入社事实和之前记住的用户原话。该结果只证明本地状态投影与演示逻辑，不作为真实模型质量证据。
5. 从聊天回人物页，展开共同经历：真实剧情包含看最后一个春天和入社，聊天记事保留原文及来源。切英文不翻译用户原话，再点返回角色，回到原作品和搜索条件，结果仍为一人。
6. 电脑英文继续原聊天，原中文消息保留；回到游戏，在原生标题页点 Continue，回到同一“真的？！ / Really?!”对白，入社状态未变。电脑侧栏可用，frame 上沿 69px、下沿 900px，无横向溢出。

## 明确保留的限制

原生游戏仍需在标题页点一次“继续 / 读档”，不能宣称点网站入口即自动回对白。公开 `xc-init` 没有 resume 意图，结局又会清空 auto；完整修复需要播放页提供明确接口，已按文件分工交接 [#158](https://github.com/storyloveai/ocai/issues/158)。本轮没有调用私有游戏对象、从宿主模拟点击 iframe、手改生成副本或修改 Claude 的播放页 / 剧本。

真实 Firebase 真人双账号 / 跨设备、模型质量及支付仍待独立环境；没有读取密钥、改远端环境、使用付费模型或操作真实积分。PR #157 和源 PR 均保持未合并。
